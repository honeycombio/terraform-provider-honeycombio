# Resource: honeycombio_environment_restriction

Restricts every Dataset in an Environment, including Datasets added later.
Only Team owners and the members of a Group that has access to the Environment can read its Datasets.

-> This feature is available as part of the [Honeycomb Enterprise plan](https://www.honeycomb.io/pricing/).

-> This resource requires the provider be configured with a Management Key with `environments:write` in the configured scopes.
  To restrict an Environment in which a Group has access to a Dataset, the key also needs `groups:write`.

The Environment is restricted while this resource exists.

* Creating this resource fails for an Environment that is already restricted. Import the restriction instead.
* If the restriction is removed outside Terraform, the next apply restricts the Environment again.
* A Classic Environment, or an Environment that Honeycomb creates and manages for the Team, cannot be restricted. The apply fails.

~> **Warning** When an Environment becomes restricted, the API clears the restriction of each Dataset in it.
  The API also revokes every grant on those Datasets, including grants made outside Terraform.
  If you unrestrict the Environment later, the API does not restore the Dataset restrictions or the grants.
  Grants to the Environment itself stay.

In a restricted Environment, the API rejects a new Dataset restriction and a new Dataset grant.
To give a Group access, grant it the whole Environment with `environment_id`.

After you restrict an Environment, remove these resources for its Datasets from your configuration:

* each `honeycombio_dataset_restriction`
* each `honeycombio_group_grant` with a `dataset_id`
* the Dataset IDs in `dataset_ids` of `honeycombio_group_grants`

The Environment restriction already cleared them in the API, so Terraform only removes them from state.
If you keep them, the next apply fails, because it tries to create them again.

~> **Warning** Do not remove them before you restrict the Environment.
  Terraform then deletes each Dataset restriction, and every Team member can read those Datasets until the Environment is restricted.

Grant the Group access before you restrict the Environment, so that the Group's members never lose access.
Add the grants to the restriction's `depends_on`, as the examples show.
Terraform then grants before it restricts, and on destroy, it unrestricts before it revokes.

~> **Warning** Deleting this resource makes every Dataset in the Environment readable by every Team member again.

To keep the Environment restricted, add `prevent_destroy` to the resource's `lifecycle` block.

When one apply deletes an Environment together with its restriction, Terraform deletes the restriction first.
If the Environment's delete then fails, for example because delete protection is on, the Environment stays, without its restriction.

## Example Usage

```terraform
resource "honeycombio_group" "sre" {
  name = "sre"
}

data "honeycombio_environment" "production" {
  detail_filter {
    name  = "name"
    value = "production"
  }
}

resource "honeycombio_group_grant" "production" {
  group_id       = honeycombio_group.sre.id
  environment_id = data.honeycombio_environment.production.id
}

# grant first, then restrict, so the Group never loses access
resource "honeycombio_environment_restriction" "production" {
  environment_id = data.honeycombio_environment.production.id

  depends_on = [honeycombio_group_grant.production]
}
```

### Several Environments

`for_each` makes one grant and one restriction for each Environment name.

```terraform
resource "honeycombio_group" "sre" {
  name = "sre"
}

# the plan fails if a name matches no Environment
data "honeycombio_environment" "prod" {
  for_each = toset(["prod-us", "prod-eu"])

  detail_filter {
    name  = "name"
    value = each.value
  }
}

resource "honeycombio_group_grant" "prod" {
  for_each = data.honeycombio_environment.prod

  group_id       = honeycombio_group.sre.id
  environment_id = each.value.id
}

resource "honeycombio_environment_restriction" "prod" {
  for_each = data.honeycombio_environment.prod

  environment_id = each.value.id

  depends_on = [honeycombio_group_grant.prod]
}
```

## Import

Environment Restrictions can be imported by the ID of the Environment. e.g.

```
$ terraform import honeycombio_environment_restriction.production hcaen_01j1jrsewaha3m0z6fwffpcrxg
```

The import fails for an Environment that is not restricted.
