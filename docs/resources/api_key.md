# Resource: honeycombio_api_key

Creates a Honeycomb API Key.
For more information about API Keys, check out [Best Practices for API Keys](https://docs.honeycomb.io/get-started/best-practices/api-keys/).

-> This resource requires the provider be configured with a Management Key with `api-keys:write` in the configured scopes.

## Example Usage

```terraform
resource "honeycombio_api_key" "prod_ingest" {
  name        = "Production Ingest"
  description = "Used by the checkout service in production"
  type        = "ingest"

  environment_id = var.environment_id

  permissions {
    create_datasets = true
  }
}

output "ingest_key" {
  value = "${honeycomb_api_key.prod_ingest.key}"
}
```

### Environment-scoped Management Keys

A `management` key is scoped to a single Environment and has `scopes` instead of `permissions`.
A key can only grant the scopes it holds itself, so the provider's key needs each scope it gives to a `management` key as well as `api-keys:write`.
It must be a team-scoped Management Key: an environment-scoped key cannot create keys.
A complete example, with the central configuration which creates the keys and the automation which uses one, can be found in the [examples directory](https://github.com/honeycombio/terraform-provider-honeycombio/tree/main/examples/samples/environment_scoped_keys).

```terraform
# A Management Key which is scoped to a single Environment.
resource "honeycombio_api_key" "prod_automation" {
  name           = "Production automation"
  description    = "Used by the production deployment pipeline"
  type           = "management"
  environment_id = var.environment_id

  # the provider's own key must hold every scope it grants
  scopes = ["datasets:read", "datasets:write"]
}

# The Key ID and Secret are only available when the key is created:
# store them in a secrets manager right away.
output "prod_automation_key_id" {
  value = honeycombio_api_key.prod_automation.id
}

output "prod_automation_key_secret" {
  value     = honeycombio_api_key.prod_automation.secret
  sensitive = true
}
```

Use `id` and `secret` of a `management` key as the provider's `api_key_id` and `api_key_secret`.
The `key` attribute is not set for `management` keys.

## Schema

### Required

- `environment_id` (String) The Environment ID the API key is scoped to.
- `name` (String) The name of the API key.
- `type` (String) The type of API key. Currently only `ingest`, `configuration`, and `management` are supported. A `management` key is scoped to the Environment given by `environment_id`.

### Optional

- `description` (String) A description of the API key, such as where it is used, of up to 2000 characters. This is not secret, so do not store secrets in it. Defaults to an empty string, so a description set outside of Terraform is removed on the next apply.
- `disabled` (Boolean) Whether the API key is disabled. Defaults to `false`.
- `permissions` (Block List) A configuration block setting what actions the API key can perform. (see [below for nested schema](#nestedblock--permissions))
- `scopes` (Set of String) The scopes granted to a `management` key, such as `datasets:read` or `datasets:write`. Required for `management` keys, and not allowed for other types. The scopes of a key cannot be changed: changing them replaces the key. The provider's own key must hold every scope it grants.
- `visible_to_members` (Boolean) Whether the key can be viewed by members and read-only users, or only owners.

### Read-Only

- `id` (String) The ID of the API Key.
- `key` (String, Sensitive) The API key formatted for use based on its type. Not set for `management` keys: use `id` and `secret`.
- `secret` (String, Sensitive) The secret portion of the API Key. It is only available when the key is created: it is not set for an imported key.

## Import

API Keys can be imported by their ID. e.g.

```
$ terraform import honeycombio_api_key.prod_ingest hcxik_01j1jrsewaha3m0z6fwffpcrxg
```

Honeycomb only returns the secret of an API Key when it is created, so an imported key has no `secret` or `key`.
If you need the secret of an imported key, replace the key: `terraform apply -replace=honeycombio_api_key.prod_ingest`.

Import `ingest` and `configuration` keys with a `permissions` block that matches the key, or Terraform plans to replace it.
